# 마중365 RAG 근거 페이지 수집기

출소자 온보딩에 필요한 제도 근거 페이지를 **헤드리스 브라우저로 열어서 화면에 실제로
보이는 텍스트만** 가져온다. HTML을 통째로 긁으면 전역 네비게이션 메뉴가 본문보다
길어서 검색 품질이 떨어지기 때문에, 사이트마다 본문 영역 선택자를 지정해 두었다.

## 준비

```bash
uv sync
uv run playwright install chromium   # 최초 1회, 약 115MB
```

## 실행

```bash
uv run python crawl.py                  # 전체 수집 (약 5분)
uv run python crawl.py --group bokjiro  # 복지로만
uv run python crawl.py --only 생계      # id나 이름에 '생계'가 들어간 것만
uv run python crawl.py --headed         # 브라우저 창을 띄워 동작 확인
uv run python crawl.py --delay 3        # 페이지 사이 대기를 늘린다
```

결과물은 `output/<그룹>/<문서id>.json`과 전체를 모은 `output/documents.jsonl`이다.
`output/`은 git에 올리지 않는다.

## 수집 대상 (`sources.json`)

| 그룹 | 건수 | 설명 |
|---|---|---|
| `bokjiro` | 2 | 복지로 생계급여·의료급여. 탭 4개를 눌러야 본문이 나오므로 별도 처리 |
| `general` | 57 | 나머지 근거 페이지. 도메인별 본문 선택자로 수집 |
| `files` | 2 | PDF·HWP 첨부파일. 본문 추출 대상이 아니라 참고 링크로만 둔다 |
| `skipped` | 4 | 중복 URL과 로그인이 필요한 신청 화면 |

대상을 추가하려면 `general` 배열에 `{id, name, url, domain}`을 넣으면 된다.
새 도메인이라면 `crawl.py`의 `CONTENT_SELECTORS`에 본문 선택자도 함께 등록한다.
등록하지 않으면 화면 전체 텍스트를 쓰면서 경고를 남긴다.

## 산출물 구조

| 필드 | 설명 |
|---|---|
| `sections` | 본문. 복지로는 지원대상·서비스 내용·신청방법·추가정보 4개로 나뉜다 |
| `title`, `summary`, `department`, `tags`, `meta` | 복지로 상단에서 파싱한 제도 요약 정보 |
| `raw_header` | 복지로 상단 영역 원문. 화면 구조가 바뀌어 파싱이 어긋나도 정보가 사라지지 않게 함 |
| `content_hash` | 본문 해시. 다시 수집했을 때 내용이 바뀌었는지 판별하는 용도 |
| `warnings` | 본문이 짧거나 서버가 차단했을 때 남는 표시 |
| `fetched_at` | 수집 시각(UTC) |

## 주의

- **정부24(`www.gov.kr`)는 일부 URL에서 자동 수집을 차단한다.** 신청 화면 계열
  3건이 "비정상 서비스 접속으로 차단되었습니다" 응답을 돌려준다. 차단을 우회하지
  않고 `warnings`에 표시만 남기므로, 해당 페이지는 사람이 직접 열어서 확인해야 한다.
  나머지 정부24 민원안내 페이지는 정상적으로 수집된다.
- **복지로는 탭을 클릭해야 본문이 DOM에 들어온다.** 첫 화면만 긁으면 지원대상 탭만 잡힌다.
- 상대는 공공기관 서버이므로 `--delay`를 0으로 두지 않는다. 기본값은 1.5초이다.
- 복지로가 간헐적으로 느리게 응답하기 때문에 페이지당 2회까지 자동으로 다시 시도한다.
- 수집 내용에 개인정보는 없다. 공개된 제도 안내문만 가져온다.
- **금액과 선정 기준은 기준연도가 바뀌면 함께 바뀐다.** `content_hash`를 비교해서
  해마다 다시 수집해야 한다.
