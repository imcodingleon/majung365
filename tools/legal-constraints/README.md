# 수용 사유별 법령 제약 수집기

수용 사유 대분류와 지원 항목의 교차점에 **법령 근거가 있는지**를 법제처
국가법령정보에서 확인해 검수용 초안을 만든다. 사람이 검수한 것만
`Majung-Backend/app/domains/knowledge/data/legal_constraints.json`으로 들어간다.

> **개발자 PC에서만 돈다.** 프로덕션 서버는 검수를 마친 JSON을 읽기만 하며,
> 법제처 인증키가 EC2에 올라가지 않는다.

---

## 왜 이렇게 하는가

출소자 인터뷰에서 들은 이야기의 상당수가 **법적으로 부정확했다.**

"사기 혐의면 통장 발급이 어렵다"는 말의 실제 근거는 「전기통신금융사기 피해 방지 및
피해금 환급에 관한 특별법」 제13조의2이고, 대상은 **접근매체를 양도·대여한 사람과
보이스피싱 목적 범죄자**다. 일반 사기죄로 형을 마친 것만으로 계좌 개설이 법으로
금지되지는 않는다.

**통념을 그대로 옮기면 앱이 사실이 아닌 체념을 심어 준다.** 조문을 대조해야
"당신의 경우는 해당하지 않습니다"라고 정확히 말할 수 있다.

---

## 준비

법제처 OPEN API 인증키가 필요하다. 무료이고 개인 계정 하나면 된다.

1. [국가법령정보 공동활용](https://open.law.go.kr/LSO/openApi/guideList.do)에서 회원가입
2. **OPEN API 신청**에서 신청서를 작성한다
3. 승인되면 인증키(OC)가 나온다 — **긴 난수가 아니라 `honggildong` 같은 짧은 아이디 형태**다

```powershell
$env:LAW_OC = "본인키"          # PowerShell
```
```bash
export LAW_OC=본인키            # bash
```

**키를 커밋하지 않는다.** `.env`와 개발 PC 환경변수에만 둔다.

의존성은 없다. 표준 라이브러리만 쓴다.

## 절차

```bash
uv run python collect.py                    # ① 조문 수집 → output/drafts/
uv run python review_report.py              # ② 검수할 것을 확인한다
#   → output/drafts/*.json을 직접 열어 채운다
uv run python merge.py --strict             # ③ 검수 안 된 게 있으면 exit 1
```

특정 항목만 다시 받으려면 id를 넘긴다.

```bash
uv run python collect.py property-R10-limited-account
```

## 검수가 무엇인가

**조문을 읽었다는 것과, 그 조문이 이 사용자 상황에 어떻게 걸리는지 판단했다는 것은
다른 일이다.** 우리가 필요한 것은 뒤쪽이다. `review_report.py`가 찍는 세 질문이
검수의 정의다.

### ① 이 조문이 그 대분류 전체에 적용되는가, 일부에만인가?

→ `relevance`에 적는다.

| 값 | 언제 |
|---|---|
| `applies` | 그 대분류 전체에 걸린다 |
| `applies_to_subset` | 일부에만 걸린다 |
| `does_not_apply` | **적용되지 않는다는 것이 근거다** |

`applies_to_subset`이면 본문에 "법으로 금지"라고 쓸 수 없다. 해당하지 않는 사람이
그 문장을 읽고 포기한다.

### ② 사용자가 겪는 어려움이 조문 때문인가, 실무 관행 때문인가?

→ 문장의 강도가 여기서 갈린다. 한도제한계좌는 조문이 아니라 금융회사 운영이므로
"법으로 막힙니다"가 아니라 "열릴 수 있습니다"다.

### ③ "해당하지 않는다"고 말할 칸이 이 항목 옆에 있는가?

→ 같은 지원 항목에 `effect: "clear"`인 초안이 있어야 한다. 없으면
`review_report.py`가 경고한다.

**제약만 수집되면 앱이 통념을 강화한다.** 사용자가 겪는 어려움의 절반은 실제
제약이 아니라 제약이 있으리라는 짐작이다.

## 채워야 하는 필드

| 필드 | 무엇을 |
|---|---|
| `effect` | `blocked` 법으로 막혀 있다 / `caution` 제약이 걸릴 수 있다 / `clear` 해당하지 않는다 |
| `severity` | `high` / `normal` / `info` — 화면이 얼마나 눈에 띄게 낼지 |
| `headline` | 명사형 제목. "한도제한계좌 안내" |
| `body` | **합니다체.** 무엇이 일어나는가 |
| `myth` | **해요체.** 무엇이 사실이 아닌가. 없으면 빈 문자열 |
| `what_to_do` | **"~해 주세요".** 사용자가 할 일. 없으면 빈 문자열 |
| `legal_basis[].quote` | 조문에서 그대로 옮긴 한 구절 |
| `legal_basis[].relevance` | 위 ①의 답 |
| `reviewed_by` | **검수자 이니셜. 비어 있으면 로더가 버린다** |
| `review_note` | 왜 그렇게 판단했는지. 다음 사람이 읽는다 |
| `applies_without_category` | 수용 사유를 밝히지 않은 사람에게도 낼 것인가 |

어체가 넷으로 갈린 것은 `copy-voice.md` 규칙 때문이다. 붙여 두면 한 갈래로 뭉개진다.

`applies_without_category`를 켠 항목은 **문구에서 수용 사유를 언급하지 않는다.**
경비업법 결격사유가 그 자리다 — 수용 사유와 무관하게 형을 산 사실에 붙으므로,
동의한 사람에게만 알리면 정작 알아야 할 사람 대부분이 못 듣는다.

## 주의

- **`output/`은 커밋하지 않는다.** 미검수 초안이 레포에 있으면 언젠가 누가 그것을
  읽는 코드를 쓴다. `tools/rag-crawler/output/`은 커밋되어 있지만 여기는 일부러
  반대로 간다
- **`_`로 시작하는 필드는 검수용이다.** `merge.py`가 지우고 백엔드 테스트가
  최종 파일에 남아 있지 않은지 검사한다
- **법은 바뀌고 우리는 그걸 모른다.** `expires_on`이 지나면 로더가 그 항목을 버리고
  부팅 로그로 알린다. 반년에 한 번 다시 돌린다
- **제한 기간을 모델링하지 않는다.** 성범죄 취업제한 기간은 판결이 정하므로 서버가
  알 수 없다. `what_to_do`에 "판결문에 적힌 기간을 확인해 주세요"로 쓴다
- 조회가 막히거나 실패하면 **우회하지 않고** 그 항목을 건너뛴다
