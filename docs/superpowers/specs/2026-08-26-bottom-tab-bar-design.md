# 하단 메뉴바 다섯 칸 — 설계

> 작성 2026-08-26 · 대상 브랜치는 `origin/main`에서 새로 딴다
> 관련 결정 기록: `_bmad-output/specs/spec-majung-2nd/decision-log-2026-08-26.md`

## 1. 무엇을 만드는가

앱 아래쪽에 다섯 칸짜리 메뉴바를 두고, 가운데 상담을 원형 버튼으로 띄운다.

| 칸 | 내용 |
|---|---|
| 홈 | 오늘의 할 일. 지금의 `/today`가 그대로 들어간다 |
| 알림 | 담당자가 방문 요청을 처리하거나 메시지를 보내면 여기에 쌓인다. 안 읽은 건수를 숫자로 띄운다 |
| 상담 | 담당자 대화와 AI 대화가 한 목록에 쌓인다. 대화방마다 안 읽은 건수를 띄운다 |
| 지도 | 위치를 기준으로 주변 기관을 지도와 목록으로 보여준다 |
| 내 정보 | 지금의 `/my-info`가 그대로 들어간다 |

## 2. 기존 계약을 두 군데 뒤집는다

### 2.1 5탭 폐기를 되돌린다 (기획서 §5.1 · `CLAUDE.md`)

본선 계약은 예선의 5탭 네비게이션을 폐지하고 단일 화면과 서류철 인덱스 탭 아코디언으로 간다고 정했다. 이 결정을 되돌려 하단 메뉴바를 되살린다.

**아코디언은 그대로 유지된다.** 메뉴바가 아코디언을 대체하지 않고, 홈 칸 안에 아코디언이 들어간다. 폐기했던 것은 화면 사이를 오가는 수단이었고, 지금 화면이 여섯 개로 늘어나 그 수단이 다시 필요해졌다.

### 2.2 구글 지도를 넣는다 (기획서 §5.4 · 보안 규칙 6번)

본선 계약은 지도를 없애고 시군구 기반 기관 안내로 대체하며, 좌표를 서버로 보내지 않고 구글 API를 쓰지 않는다고 정했다. 이 결정을 되돌려 구글 지도를 넣는다.

**감수하는 것을 분명히 적어 둔다.** 지도를 내 위치 중심으로 그리려면 좌표를 구글에 넘겨야 한다. 우리 서버에는 여전히 좌표가 가지 않지만, 출소자의 현재 위치가 구글에 도달한다. 팀 회의에서 이 정도는 감수할 수 있다고 판단했다.

**키 제한이 유일한 방어막이다.** `EXPO_PUBLIC_GOOGLE_MAPS_KEY`는 접두사 그대로 웹 번들에 박힌다. 구글 클라우드 콘솔에서 HTTP 리퍼러를 배포 도메인으로 묶고 쓰는 API를 Maps JavaScript로 한정해야 한다. 이것은 코드가 아니라 콘솔 설정이며 사람이 직접 해야 한다.

## 4. 구조

### 4.1 라우팅

`(tabs)` 그룹을 되살린다. 괄호로 묶은 폴더는 주소에 나타나지 않으므로 **배포된 웹 주소가 바뀌지 않는다.**

```
src/app/
  (tabs)/
    _layout.tsx      하단 바
    today.tsx        홈        → /today
    alerts.tsx       알림      → /alerts
    chats.tsx        상담      → /chats
    map.tsx          지도      → /map
    my-info.tsx      내 정보   → /my-info
  signup.tsx         탭 밖
  retake.tsx         탭 밖
  pamphlet.tsx       탭 밖
  admin.tsx          탭 밖
  index.tsx          진입 분기
```

가입하는 중에 하단 바가 보이면 안 되므로 `signup`을 비롯한 넷은 탭 밖에 둔다.

탭마다 화면 상태가 따로 유지된다. 지도를 보다가 홈에 갔다 돌아와도 보던 자리가 남는다.

### 4.2 아이콘

**지워진 PNG를 되살리지 않고 SVG로 다시 그린다.** PNG는 활성 남색과 비활성 회색이 파일에 구워져 있어 색을 바꿀 수 없고, 직전 커밋 `7cd6607`이 이모지를 걷어내고 SVG로 통일한 작업이라 PNG를 되살리면 그 통일이 깨진다.

`Icon.tsx`의 규칙을 그대로 따른다. 24×24 격자에 2px 획, 둥근 마감이다.

| 칸 | 아이콘 | 상태 |
|---|---|---|
| 홈 | 집 | 새로 그린다 |
| 알림 | 종 | `bell` 있음 |
| 상담 | 말풍선 | `chat` 있음 |
| 지도 | 압정 | `pin` 있음 |
| 내 정보 | 사람 | 새로 그린다 |

### 4.3 숫자 배지

안 읽은 건수를 아이콘 오른쪽 위에 띄운다. 두 자리를 넘으면 `99+`로 줄인다.

**0이면 그리지 않는다.** 0을 띄우면 읽을 것이 있다는 뜻으로 보인다.

## 5. 칸별 설계

### 5.1 홈

지금의 `/today`를 그대로 옮긴다.

**화면 안의 이동 버튼 둘을 지운다.** 지금 `today.tsx`에 "우리 동네 기관 찾기"(`onOpenNearby`)와 "내 정보"(`onOpenMyInfo`)가 있는데, 하단 바가 생기면 같은 곳으로 가는 길이 둘이 된다. 하단 바 쪽만 남긴다.

### 5.2 알림

**새로 저장하지 않는다.** 이미 있는 두 가지를 시간순으로 합쳐 목록을 만든다.

| 재료 | 출처 |
|---|---|
| 방문 요청 상태 변화 | `GET /api/visits`의 `status`·`confirmed_at`·`proposed_at` |
| 담당자 메시지 안 읽음 | 같은 응답에 추가될 `unread` 필드 |

읽었는지 여부는 **기기에 마지막으로 본 시각 하나만** 남긴다. 서버에 알림 테이블을 만들지 않는 이유는 데이터 최소화 원칙 때문이다. 알림을 서버에 쌓으면 "누가 언제 어느 기관과 연락했는가"가 한 줄씩 남고, 그것은 보관·파기 대상(§9.4)이 늘어나는 일이다.

**감수하는 것.** 기기를 바꾸면 읽음 표시가 따라오지 않아 알림이 다시 안 읽은 것으로 보인다. 나중에 푸시 알림이 필요해지면 그때 서버 저장으로 옮긴다.

### 5.3 상담

두 종류의 대화를 한 목록에 섞는다.

| 종류 | 단위 | 연결 방식 |
|---|---|---|
| 담당자 대화 | 방문 요청 하나 | Socket.IO |
| AI 대화 | 할 일 하나 | 기존 `useTaskThreads` |

각 줄에 상대 이름, 마지막 메시지, 시각, 안 읽은 건수를 띄운다. 누르면 하던 자리에서 이어진다.

**서버가 준 거절 문구를 그대로 쓴다.** 방이 안 열리는 경우가 넷 있고 문구가 계약에 정해져 있다(`Majung-Backend/docs/socket-contract.md`). 특히 없는 요청과 남의 요청에 **같은 문구**를 쓴다. 구분해 주면 남의 방 번호를 찾는 데 쓰이기 때문이다.

**필드 이름을 계약대로 쓴다.** 소켓은 `senderRole`·`clientMsgId`이고 REST는 `route_id`·`client_msg_id`다. 표기가 서로 다른 것은 의도된 것이며 계약 문서에 근거가 적혀 있다. 이름이 어긋나면 오류가 나지 않고 `undefined`가 되어 말풍선이 한쪽에 전부 붙는다.

### 5.4 지도

예선 `MapScreen`을 되살리고 데이터가 나오는 곳만 바꾼다.

| 구성 | 처리 |
|---|---|
| 검색창 · 카테고리 네 개 · 즐겨찾기 · 전화 · 길찾기 | 되살린다 |
| 지도 | `CenterMap.web.tsx`를 되살린다. 키가 이제 있다 |
| 기관 데이터 | 예선 `demoCenters.ts`를 버리고 `getInstitutions`·`getDistrictOffices`로 바꾼다 |
| 위치 | 기존 `useRegionLookup`을 쓴다 |
| 아이콘 PNG 다섯 개 | SVG로 다시 그린다 |

**위치를 못 받으면 지역을 직접 고르게 한다.** 지금 `/nearby`의 `RegionPicker`가 그 화면이며, 그대로 이어 붙인다.

### 5.5 내 정보

지금의 `/my-info`를 그대로 옮긴다.

## 6. 함께 고치는 버그 — 담당자 메시지가 사용자에게 도달하지 않는다

### 증상

담당자 계정으로 답장을 보냈는데 사용자 쪽에 그 메시지가 나타나지 않는다.

### 원인

`src/app/today.tsx`의 두 줄이 같은 것을 부른다.

```
112:  onOpenChat={chat.open}                          AI와 대화하기
125:  onOpenStaffChat={() => chat.open(taskId)}       담당자와 이야기하기
```

여기서 `chat`은 `useTaskThreads()`, 즉 AI 채팅이다. **"담당자와 이야기하기"를 눌러도 AI 채팅창이 열린다.**

근거 셋.

1. `src/admin/`을 뺀 전체 소스에 소켓 코드가 한 줄도 없다. 사용자 쪽에 메시지를 받을 통로 자체가 없다
2. `useVisitChat`을 쓰는 곳은 `src/admin/views/AdminApp.tsx` 한 군데뿐이다
3. 사용자 쪽 버튼이 AI 채팅 훅으로 연결되어 있다

담당자는 소켓 방에 답을 쓰고 사용자는 AI에게 말하고 있었다. 서버는 정상이며, 담당자가 보낸 메시지는 저장되어 있으나 꺼내 보는 화면이 없었을 뿐이다.

### 고치는 방법

1. `useVisitChat`을 `src/admin/`에서 공용 자리로 옮긴다
2. 사용자용 담당자 채팅 화면을 만든다. 담당자 쪽 `StaffChatScreen`과 짝을 이룬다
3. `today.tsx`의 "담당자와 이야기하기"가 그 화면을 열게 한다

### 재발을 막는 확인 항목

이 결함은 한쪽만 만들고 짝을 만들지 않아 생겼다. 작업을 마칠 때 다음을 센다.

- 담당자 쪽에 있는 기능마다 사용자 쪽 짝이 있는가
- 서버에 있는 이벤트마다 그것을 받는 화면이 있는가
- 저장하는 곳마다 되살리는 곳이 있는가

## 7. 서버에 요청할 것

`backend` 세션에 두 가지를 요청한다.

| # | 내용 | 규모 |
|---|---|---|
| 1 | `GET /api/visits` 응답에 안 읽은 건수 필드를 더한다 | 작다. `unread_for()`가 이미 있고 `VisitOut`에 필드를 붙이면 된다 |
| 2 | 담당자가 채팅방에 들어가 대화를 읽으면 감사 로그를 남긴다 (코드 리뷰 M4) | 중간. `0003_staff_account.sql`이 `action` 값에 `chat`을 이미 적어 두었다 |

2번은 상담 탭을 만들면 더 중요해진다. 방이 기관 단위로 열려서 같은 기관 담당자가 임의 `visitId`로 남의 대화를 읽을 수 있고 지금은 흔적이 남지 않는다.

## 8. 하지 않는 것

- **푸시 알림.** 앱을 켰을 때만 알림을 본다. 푸시는 기기 토큰을 서버에 저장해야 하고, 그것은 §9.4 보관 대상이 늘어나는 일이다
- **알림 테이블.** 5.2에 적은 이유로 만들지 않는다
- **채팅 이미지 전송.** 신분증이나 서류 사진이 오가면 위험만 커진다. 계약(§7.3)이 이미 금지한다
- **방을 사용자와 지부로 영구히 묶기.** 방은 방문 요청 단위이며 요청이 끝나면 닫힌다
- **네이티브 지도.** 배포판이 웹이므로 웹 구현만 살린다. 네이티브는 대체 화면으로 둔다

## 9. 확인 방법

| 대상 | 확인 |
|---|---|
| 하단 바 | 다섯 칸이 모두 눌리고 주소가 기존과 같다 |
| 홈 | 아코디언 동작이 그대로다. 화면 안 중복 버튼이 없다 |
| 알림 | 방문 상태가 바뀌면 목록에 뜬다. 읽으면 배지가 사라진다 |
| 상담 | **담당자가 보낸 메시지가 사용자 화면에 나타난다.** 이것이 6절 버그의 완료 조건이다 |
| 상담 | 끊겼다가 다시 보내도 대화가 두 번 쌓이지 않는다 (`clientMsgId`) |
| 지도 | 위치를 켜면 주변 기관이 뜨고, 거부하면 지역 직접 선택으로 넘어간다 |
| 배포 | 배포 후 파일 해시를 대조한다. 명령이 성공했다고 서버가 최신인 것은 아니다 |

## 10. 순서

1. 하단 바와 아이콘을 되살린다. 홈·내 정보를 붙이고 나머지는 빈 화면으로 둔다
2. 지도를 되살리고 데이터를 갈아끼운다
3. 담당자 채팅을 사용자 쪽에 잇는다 (6절 버그 수정)
4. 대화 목록 화면을 만든다
5. 알림 목록 화면을 만든다
6. 서버 두 건이 오면 배지 숫자를 잇는다

1번이 끝나면 배포판에서 눈으로 확인할 수 있다. 3번은 서버를 기다리지 않아도 되므로 6번보다 앞에 둔다.
