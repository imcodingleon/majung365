# 관리자 앱 분리 — 설계

> 작성 2026-08-26 · 대상 브랜치는 `origin/main`에서 새로 딴다
> 관련 계약: 기획서 §8(관리자 앱) · §8.4-4 · §12-26 · `CLAUDE.md` 보안 규칙

## 1. 무엇을 만드는가

같은 코드베이스에서 앱을 둘 낸다. 지금까지 하나였던 빌드를 **출소자 앱**과 **관리자 앱**으로 가른다. 코드를 옮기거나 복제하지 않고, 환경변수 하나로 무엇을 싣고 어디서 시작할지만 바꾼다.

관리자 앱은 **본선 시연용이다.** 팀원이 담당자 역할로 시연하며 실제 공단 직원은 쓰지 않고 데이터도 가상이다. 따라서 안드로이드와 iOS 모두 **내부 테스트 트랙**까지만 간다.

## 2. 왜 지금 할 수 있는가

새로 정하는 것이 아니다. 기획서 §8이 이미 "웹 어드민이 아니라 별도 앱"으로 확정했고, 코드도 그 전제로 준비되어 있다.

**§8.2가 "기능이 아니라 전제 조건"이라고 규정한 넷이 모두 구현되어 있다.**

| # | 전제 조건 | 현재 상태 |
|---|---|---|
| 1 | 담당자 계정 체계 | 서버 인증(`POST /api/staff/login`)이 붙어 있다. `demoCredentials`는 지워졌다 |
| 2 | 접근 통제 | 자기에게 온 요청만 열린다 |
| 3 | 열람 감사 로그 | `Majung-Backend/app/domains/staff/infrastructure/supabase_repository.py:127` |
| 4 | 자동 로그아웃 | 유휴 5분(`IDLE_LOGOUT_MS`), 토큰을 기기에 저장하지 않는다 |

`src/admin/`도 이미 나뉘어 있다. 밖으로 나가는 의존은 `@/shared/*`와 `@/features/visit/*` 둘뿐이며, 둘 다 양쪽 앱이 공유할 계층이므로 끊을 필요가 없다.

## 3. 요구사항이 한 방향이다

설계를 가른 판단이다. **두 앱이 서로를 막아야 하는 것이 아니다.**

- **출소자 앱에 관리자 화면이 들어가면 안 된다.** §8.4-4와 §12-26이 정한 것이고, `metro.config.js`의 blockList이 이미 지키고 있다. 2026-08-26 현재 Play 내부 테스트에 올라간 AAB에는 관리자 화면 문자열이 들어 있지 않다
- **관리자 앱에 출소자 화면이 들어가는 것은 보안 문제가 아니다.** 불필요할 뿐이다

그런데도 관리자 앱에서 출소자 화면을 빼기로 한 이유는 크기가 아니라 **Play에 내는 선언의 정직성**이다. 지도와 위치 코드가 실린 채로 선언을 쓰면 앱이 실제로 하는 일과 어긋난다.

내부 테스트만 하는 앱은 데이터 보안 양식이 면제될 수 있으나, 타겟층·광고·콘텐츠 등급 같은 항목은 그대로 묻는다. 그리고 **나중에 트랙을 넓히면 양식이 따라붙는다.** 그때 앱 안에 있는 것과 선언이 어긋나 있으면 고치기 번거롭다.

## 4. 접근안과 선택

| 안 | 방법 | 판정 |
|---|---|---|
| **A** | 라우트 루트를 `src/app/`와 `src/app-admin/`로 가른다 | **채택** |
| B | 루트는 하나로 두고 진입 화면만 가른다 | 물러날 자리로 남긴다 |
| C | 레포를 아예 분리한다 | 접는다. 일정에 과하고 §8도 "코드베이스는 공유하더라도"라고 적었다 |

A안의 유일한 실질 위험은 `expo-router` 설정 플러그인의 `root` 옵션이 공식 설명에 **"Avoid using this property"**라고 달려 있다는 점이다. 빌드 한 번이면 판명되므로 감수하고, 걸리면 B안으로 물러난다(§10).

## 5. 설계

### 5.1 빌드 위상

환경변수 `APP_VARIANT` 하나로 갈린다. 값이 없으면 출소자 앱이고 `admin`이면 관리자 앱이다. **기본값이 출소자인 것이 중요하다.** 잊었을 때 안전한 쪽으로 남는다.

| | 출소자 앱 | 관리자 앱 |
|---|---|---|
| `APP_VARIANT` | (없음) | `admin` |
| 라우트 루트 | `src/app/` | `src/app-admin/` |
| 표시 이름 | 마중365 | 마중365 담당자 |
| slug | `majung365` | `majung365-admin` |
| scheme | `majung365` | `majung365admin` |
| 안드로이드 패키지 | `com.superbuilders.majung365` | `com.superbuilders.majung365.admin` |
| iOS 번들 ID | `com.superbuilders.majung365` | `com.superbuilders.majung365.admin` |
| EAS 프로젝트 | `bb610f96-e51d-4f6e-a106-e113ea8a7cb3` | 새로 만든다 |
| `typedRoutes` | 켠다 | 끈다 |

패키지 이름이 다르므로 **한 기기에 둘을 함께 깔 수 있다.** 시연에서 한 폰으로 양쪽을 보여줄 수 있다.

`src/admin/`, `src/shared/`, `src/features/visit/`는 양쪽이 그대로 공유한다. 백엔드도 같은 서버(`https://3-34-251-223.sslip.io`)를 쓴다.

### 5.2 파일 구조

새로 만드는 것은 둘뿐이다.

**`src/app-admin/_layout.tsx`** — 관리자용 루트 레이아웃. `SafeAreaProvider`·`AppFrame`·`Stack`·`StatusBar`까지는 출소자와 같다. 다만 **`useRestoreSession`을 넣지 않는다.** 담당자는 토큰을 기기에 저장하지 않으므로(§8.3) 되살릴 세션이 없고, 넣으면 출소자 세션을 담당자 앱이 들여다보는 셈이 된다.

`AppFrame`은 웹에서만 폭을 묶고 네이티브에서는 아무것도 하지 않으므로, 넣어 두어도 앱 동작에 영향이 없고 웹 모양은 지금 그대로 유지된다.

**`src/app-admin/index.tsx`** — `src/admin`의 `AdminApp`을 그린다.

**`src/app/admin.tsx`는 지우지 않는다.** 시연 대체 경로인 웹 `/admin`이 이 파일로 열린다(§9).

### 5.3 `app.json` → `app.config.js`

정적 JSON으로는 변형을 가를 수 없으므로 바꾼다. 지금 `app.json`에 있는 값은 모두 옮기고, 아래만 변형에 따라 갈린다.

- `name` · `slug` · `scheme`
- `ios.bundleIdentifier` · `android.package`
- `extra.eas.projectId`
- `plugins`의 `["expo-router", { root }]`
- `experiments.typedRoutes`

`typedRoutes`를 관리자에서 끄는 이유는 루트가 바뀌면 생성되는 라우트 타입도 함께 바뀌기 때문이다. 켜 둔 채 변형을 오가면 출소자 코드 쪽에 헛된 타입 오류가 남는다.

`ios.buildNumber`와 `android.versionCode`는 두 앱이 별개로 센다. 관리자 앱도 1에서 시작한다.

**아이콘을 갈라야 한다.** 두 앱을 한 기기에 함께 깔면 아이콘이 같아 시연하는 사람이 어느 쪽인지 구별하지 못한다. 관리자 앱은 바탕색을 달리한 아이콘을 따로 만들어 `assets/images/`에 두고, 표시 이름("마중365 담당자")과 함께 눈으로 갈리게 한다. 스플래시 배경색도 같은 값을 쓴다.

### 5.4 `metro.config.js`

한 줄만 고친다. 관리자 변형일 때 blockList이 풀려야 한다. 안 풀면 관리자 앱이 자기 구현인 `@/admin`을 찾지 못해 빌드가 깨진다.

```js
const INCLUDE_ADMIN = process.env.INCLUDE_ADMIN === "1" || process.env.APP_VARIANT === "admin";
```

**출소자 빌드의 동작은 그대로다.** 기본값이 제외인 성질을 건드리지 않는다. 파일 위쪽 주석의 "별도 빌드가 생기면 이 blockList는 지운다"는 문장은 사실과 달라지므로 함께 고친다. **지우면 안 되고 조건이 하나 늘 뿐이다.** 출소자 빌드에서는 앞으로도 계속 막아야 한다.

관리자 변형에서 출소자 라우트가 빠지는 것은 blockList이 아니라 루트가 처리한다. `require.context`가 `src/app-admin/`만 훑으므로 `src/app/`은 열거되지 않는다.

### 5.5 `eas.json`

프로필 둘을 더하고 `env`로 `APP_VARIANT`를 넘긴다.

| 프로필 | 용도 | 산출물 |
|---|---|---|
| `admin-preview` | 기기에 바로 깔아 확인 | APK · 내부 배포 |
| `admin-production` | Play 내부 테스트 제출 | AAB |

`submit`에도 `admin-production`을 더한다. 서비스 계정 키(`google-play-service-account.json`)와 `track: "internal"`은 출소자 앱과 같은 값을 쓴다. 키 하나로 같은 개발자 계정의 두 앱을 모두 올릴 수 있다.

## 6. EAS와 Play 등록

**`eas init`은 동적 설정 파일에 프로젝트 ID를 써 넣지 못한다.** 관리자용 EAS 프로젝트를 만든 뒤 발급된 ID를 `app.config.js`에 직접 적어야 한다.

EAS 환경변수는 프로젝트 단위이므로 **새 프로젝트에 `EXPO_PUBLIC_API_URL`을 다시 등록한다.** 값은 출소자 앱과 같다.

Play는 새 앱으로 등록하고 내부 테스트 트랙에 올린다. 출소자 앱에서 한 번 채운 선언을 콘솔이 요구하는 만큼 다시 채운다.

**출소자 앱의 답을 그대로 옮겨 적지 않는다.** 관리자 앱은 타인의 정보를 열람하는 도구라 답이 다르다. 데이터 보안 양식을 요구받으면 특히 그렇다. 스크린샷도 관리자 화면으로 새로 뽑는다. `APP_VARIANT=admin`으로 로컬 서버를 띄우고 출소자 앱에서 쓴 방식(브라우저를 9:16 비율로 잡아 캡처)을 그대로 쓴다.

iOS는 번들 ID만 잡아 두고 애플 개발자 팀 반영이 끝난 뒤 진행한다. 그때 기기 등록이 필요 없는 TestFlight 내부 테스트가 ad-hoc 배포보다 나은지 함께 판단한다.

## 7. 검증

**다섯 가지를 모두 확인해야 끝이다.** 이 프로젝트 결함의 반복 모양이 "한쪽만 고치고 짝을 안 보는 것"이므로 양쪽을 다 센다.

| # | 확인할 것 | 통과 기준 |
|---|---|---|
| 1 | `APP_VARIANT=admin`으로 띄운다 | 첫 화면이 담당자 로그인이다 |
| 2 | 아무 값 없이 띄운다 | 출소자 첫 화면이 뜨고 `/admin`이 없다 |
| 3 | 관리자 빌드 번들 | 출소자 화면 문자열이 검출되지 않는다 |
| 4 | 출소자 빌드 번들 | **관리자 화면 문자열이 검출되지 않는다** — 지금 상태의 회귀 확인이다 |
| 5 | 웹 내보내기 | `/admin`이 여전히 열린다 — 시연 대체 경로가 깨지지 않았다 |

3번과 4번의 문자열 검색은 **인코딩에 두 번 걸린다. 둘 다 "없다"는 거짓 결과를 낸다.**

1. **Git Bash의 `grep`이 한글을 놓친다.** 파이썬이나 Node로 UTF-8을 명시해 센다
2. **번들이 한글을 `\uXXXX`로 이스케이프해 내보낸다.** 리터럴만 세면 담당자 화면이 실려 있어도 0으로 보인다. 2026-08-26에 실측했다 — `들어가기`는 리터럴 0, 이스케이프 2였다. **리터럴과 이스케이프를 모두 세거나, `AdminApp`·`AdminLoginScreen` 같은 ASCII 식별자를 함께 본다**

두 번째가 특히 위험하다. 4번은 스토어에 나가는 번들을 지키는 자리인데, 리터럴만 세면 **아무것도 지키지 않으면서 통과했다고 말한다.**

## 9. 의도적으로 남긴 미결 — §12-26

**공개 웹 `majung365.vercel.app/admin`에 담당자 로그인 화면이 열리는 상태를 이번에 닫지 않는다.** 팀 결정이며 근거는 다음과 같다.

- 시연 중 앱이 뜨지 않을 때 쓸 **대체 경로**가 필요하다
- 로그인이 목업이 아니라 **서버 인증**이다. 번들에 자격이 박혀 있던 문제(§12-26-1)는 이미 해소되었다
- 시연 데이터가 **가상**이라 실제 출소자 정보가 걸려 있지 않다

배경으로 기록해 둔다. 커밋 둘이 서로 반대로 서 있다.

| 날짜 | 커밋 | 내용 |
|---|---|---|
| 2026-08-23 | `a6b126f` | 담당자 화면을 빌드에서 뺐다 (blockList, 기본 제외) |
| 2026-08-25 | `266e0cf` | 배포에는 다시 넣었다 (`vercel.json`의 `INCLUDE_ADMIN=1`) |

나중 것이 이기므로 웹은 담당자 화면을 싣는다. **네이티브 스토어 빌드는 blockList이 지키고 있어 영향이 없다.**

**지금 이미 열려 있다.** 2026-08-26에 실측했다. `https://majung365.vercel.app/admin`이 200을 반환하고, 그 페이지가 부르는 번들에 `AdminApp`·`AdminLoginScreen`·`useAdminSession`·`RequestListScreen`이 모두 들어 있다. 나중에 열리는 것이 아니라 이미 공개된 상태다.

처음에는 "아직 새지 않는다"고 판단했는데 **틀렸다. 한글 리터럴만 세다가 이스케이프된 문자열을 놓쳤다.** 위 §7의 두 번째 함정에 그대로 걸린 사례다.

**이 설계는 그 상태를 유지할 뿐 악화시키지 않는다.** 검증 5번이 그것을 확인하는 자리다. 시연이 끝나면 `vercel.json`의 `INCLUDE_ADMIN=1`을 지워 닫는다.

## 10. 위험과 물러날 자리

| 위험 | 징후 | 물러날 자리 |
|---|---|---|
| `root` 옵션이 권장되지 않는다 | 웹 내보내기 실패, 라우트를 못 찾음 | **B안** — 루트를 공유하고 관리자 변형에서 첫 화면만 관리자로 넘긴다. 관리자 앱에 출소자 화면이 함께 실리는 것을 감수하고, Play 데이터 보안 양식을 그에 맞게 쓴다 |
| `typedRoutes`가 루트 전환에서 꼬인다 | 출소자 코드에 헛된 타입 오류 | 관리자 변형에서 끈다. 설계에 이미 반영했다 |
| `app.config.js` 전환에서 값이 빠진다 | 빌드는 되는데 아이콘·스플래시가 사라진다 | 전환 직후 `npx expo config --type public`으로 두 변형의 결과를 눈으로 대조한다 |
