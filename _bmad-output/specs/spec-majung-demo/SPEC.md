# [마중] 예선 웹 프로토타입 데모

## Why

KDT 해커톤 예선(7/10 13:00 제출) 통과와 7/8 공단 인터뷰 시연이라는 마감(mandate)이 동력. 출소자는 출소 직후 무엇을 어디서 해결할지 몰라 첫 몇 주에 막히고, 공단 직원은 같은 안내를 반복한다. 이 데모는 "상황을 말하면 급한 일을 정리해 실행 가능한 안내로 바꾸는" 한 장면을 실제로 작동시켜, 기획안의 주장(직원 반복 응대를 AI가 1차 처리)을 증명하는 물증이다. 데모 범위는 출소자 화면 플로우만이며, 제품 본체 포지셔닝(공단 직원 AX)·BM·본선 계획은 forge 원장이 담당한다.

## Capabilities

- **CAP-1 상황 입력**
  - **intent:** 사용자가 자기 상황을 두 표면에서 입력할 수 있다 — ①온보딩 구조화 질문(카드형 선택지, 5단계 진행률 표시; 질문 내용은 임시, 7/8 인터뷰 후 확정) ②챗봇 자유 텍스트·프리셋 칩(예: "오늘 뭐 해야 해요?" / "근처 센터 어디예요?").
  - **success:** 온보딩은 선택지 탭만으로 완주 가능하고, 챗봇은 프리셋 탭 1회 또는 한 문장 입력만으로 다음 단계가 시작된다. 카피가 거부감·반발심을 만들지 않는다(팀 검수).

- **CAP-2 AI 우선순위 정리 (triage)**
  - **intent:** 입력된 상황을 6개 영역(신분 재건 / 긴급복지·생계 / 주거 / 취업 / 의료·마음 / 채무)으로 분석해 가장 급한 2~3가지를 우선순위로 제시한다.
  - **success:** demo-scenario.md의 입력 3종 각각에 대해 기대 영역이 우선순위 상위에 포함되고, 응답이 대화 맥락에서 어긋나지 않는다.

- **CAP-3 정보 안내 (2-tier)**
  - **intent:** ①제도·신청·서류 등 정확성이 필수인 정보는 지식베이스(법무보호복지공단·정부24·복지로·고용24 출처)에서 매칭해 카드로 안내하고 근거 제도명을 명시한다. ②일상 질문(카드 재발급 방법·근처 정보 등)은 Claude 네이티브 웹 검색(공공 도메인 한정)으로 답한다.
  - **success:** 제도 카드는 ①제도명 ②신청 장소 ③필요 서류 ④다음 단계 포함 + KB 항목만 인용. 일상 답변은 공공 도메인 출처 기반. 두 경우 모두 쉬운 말 기준(demo-scenario.md 톤 규칙) 통과.

- **CAP-4 체크리스트 변환**
  - **intent:** 안내된 항목을 단계별 체크리스트(로드맵 화면)로 변환해, 챗봇이 낯선 사용자도 해야 할 일을 한눈에 볼 수 있다.
  - **success:** triage 결과에서 로드맵 화면으로 전환되고, 각 항목이 단계 카드(긴급도·설명·바로가기, 기한 경고 포함)로 표시된다. 완료 체크 상호작용은 본선 몫 — 예선은 표시만으로 충분.

- **CAP-5 지도 위치 안내**
  - **intent:** 체크리스트 항목과 연결된 주변 지원기관(공단 지부·주민센터·고용센터)의 위치·전화·운영시간을 지도로 보여준다.
  - **success:** 데모 데이터 기관들이 지도에 마커로 표시되고 상세(전화·운영시간)가 열린다.

## Constraints

- **일정:** 7/10 13:00 제출. 7/8 공단 인터뷰에서 라이브 시연 가능해야 함 → 실질 개발 마감 D-3.
- **플랫폼:** 웹. 네이티브/하이브리드 앱은 본선 몫.
- **포지셔닝 카피:** A 쐐기(공단 시설 내 온보딩) 프레임. "출소 그다음 날부터 앱을 켠다"류 B 프레임 문구 금지.
- **저리터러시 UI:** 디지털 단절 사용자 전제 — 쉬운 말, 큰 글씨, 프리셋 버튼 우선, 판단하지 않는 톤.
- **디자인 준수:** 서비스명 표기는 "마중365". 하단 네비는 5탭(홈/로드맵/상담/지도/내 정보)으로 전 화면 통일 — 로드맵 화면(2:1614)이 정본. 온보딩 개인정보 문구는 시안 원안 유지.
- **보안 최우선 (1번 원칙):** 출소 사실 자체가 민감정보 — 편의성과 충돌 시 항상 보안 선택. 데이터 최소화(수집·저장·로그 기본 0), 대화 내용도 민감정보 취급(로그에 원문 금지), 서드파티 추가는 사용자 확인 필수. 상세는 루트 CLAUDE.md §보안.
- **개인정보:** 익명 사용. 실명·민감정보 수집/저장 없음. 지식베이스는 공개 데이터만.
- **LLM:** Claude API (주최측 지원 대상). 웹 검색은 네이티브 `web_search` 서버 툴만 사용 — `allowed_domains`를 공공 도메인으로 제한, `max_uses` 상한 설정, 검색 쿼리에 사용자 개인 상황 서술 배제(시스템 프롬프트 지시).

## Non-goals

- 직원 대시보드·상담 전 요약 카드 화면 (본선 고려; 7/8 인터뷰용 종이 목업은 코드 밖에서 별도 제작)
- 캘린더·알림, 진행 상태 추적 (기획안 To Be에는 있으나 예선 범위 아님)
- 계정·로그인·사용자 데이터 영속화
- 실시간 크롤링·대규모 벡터 RAG (사전 큐레이션 지식베이스로 대체)
- 재범률 연동 성과 지불 등 BM 구현물
- 홈 화면 기능 (네비 탭·버튼은 존재해도 되나 착지 화면·서비스 그리드 기능은 만들지 않음 — 팀 결정 2026-07-05)
- 음성 입력 (챗봇 입력창의 마이크 아이콘은 장식으로만)

## Success signal

7/8 공단 인터뷰에서 [상황 입력 → 급한 일 정리 → 체크리스트 → 지도] 플로우가 김판수 시나리오로 끊김 없이 라이브 시연되고, 같은 빌드가 7/10 제출물에 포함된다. 데모를 본 공단 직원이 "이 안내라면 반복 문의가 줄겠다"는 반응 여부를 인터뷰 기록으로 남긴다.

## Assumptions

- 예선 데모의 지식베이스는 6영역 × 소수 제도의 사전 큐레이션(JSON/문서)으로 충분하다 — 벡터DB·실시간 검색 불요.
- 데모 시나리오는 김판수 페르소나(5년 복역, 무연고 40대) 기준, 지도 데이터는 서울(서부지부 관할) 중심.
- UI 언어는 한국어 단일.
