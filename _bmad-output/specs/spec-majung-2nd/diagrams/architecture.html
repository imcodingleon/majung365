Frontend 요청 한 번이 Backend를 지나며 어떻게 처리되는지 — 순서 계산(그래프 알고리즘)은 코드가 맡고, LLM은 발화당 2회(구조화 출력 1회 · RAG 응답 생성 1회)만 호출된다. 완료하면 그래프를 다시 계산해 다음 과제를 연다 — 이 루프가 서비스의 형태다.

왜 그래프 알고리즘이 LLM을 대체하나

무엇을 먼저 해야 하는지 계산은 답이 정해진 문제다. LLM에 맡기면 같은 상황에서 다른 순서가 나올 수 있고, 잘못된 순서는 사용자를 헛걸음시킨다. 제도 간 선행조건을 DAG로 구성해 두고 위상 정렬(Kahn's Algorithm, O(V+E))로 계산한다. LLM은 언어를 다루는 입구(구조화 출력)와 출구(RAG 응답 생성)에만 둔다.

왜 PII 익명화를 로컬에서 하나

대화를 그대로 외부 API로 보내면 그 순간 통제를 잃는다. 서버 안의 로컬 AI가 이름·연락처 같은 개인정보를 placeholder로 치환한 문장만 내보내고, 응답이 돌아오면 de-tokenize로 원래 값을 복원해 사용자에게 보여준다. 외부 API는 어느 시점에도 실제 개인정보를 받지 않는다.

왜 지식베이스를 JSON + 하이브리드 검색으로 두나

제도 수가 수십 단위이고 갱신 주기가 길어 DB는 과설계다. 검색은 키워드(BM25)와 벡터 임베딩을 함께 쓴다 — 제도명을 아는 발화는 키워드가, 상황만 말하는 발화는 벡터가 받는다.
