마중365 활용 기술

LLM은 양 끝에서 두 번만 부른다 — 말을 데이터로 바꿀 때, 데이터를 말로 바꿀 때. 그 사이에서 무엇을 먼저 할지 정하는 일은 코드가 한다. 같은 입력이면 항상 같은 답이 나와야 하기 때문이다.

왜 가운데를 LLM으로 안 하나

“무엇을 먼저 해야 하는가”는 답이 정해져 있는 문제다. 통장을 만들려면 신분증이 있어야 하고, 신분증을 만들려면 주소지가 있어야 한다. LLM에 맡기면 같은 사람에게 물을 때마다 순서가 달라지고, 잘못된 순서는 사용자를 헛걸음시킨다. 제도 사이의 선행조건을 그래프로 만들어 두고 위상 정렬로 “지금 막힌 게 없는 항목”을 뽑는다. O(V+E)라 제도가 늘어도 느려지지 않는다.

왜 음성을 직접 돌리나

출소 사실은 새어 나가면 사회 복귀 자체가 무너지는 정보다. 음성 파일을 외부 STT에 올리지 않고 서버에서 직접 처리하고, 끝나면 바로 지운다. 음성은 기능이 아니라 접근성 수단이다 — 말하면 입력창에 글로 적히고, 사용자가 고쳐서 보낸다.

한 번에 하나만 주는 이유

할 일 목록을 다 주면 어디부터인지 몰라 다시 막힌다. 실행 가능한 항목이 여럿이면 기한이 급한 것 → 완료 시 열리는 게 많은 것 순으로 하나만 고른다. 완료하면 다음이 열린다.
