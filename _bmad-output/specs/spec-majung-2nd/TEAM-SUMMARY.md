## 1. 한 줄로

> 상황을 말하면 **제도 간 선행조건 그래프**를 연산해 **지금 할 수 있는 첫 과제 하나**를 준다. 완료하면 다음이 열린다.

**핵심은 챗봇입니다.** 음성은 기능이 아니라 입력 수단(GPT 앱의 음성 받아쓰기와 동일)입니다.

## 2. 이번에 바뀐 것 2가지

**① 음성 감정 인식을 범위에서 뺐습니다**
- 사유: 멘토 판단 — 핵심기능으로 삼기엔 부족. 멘토는 *"김밥천국이 아니라 미슐랭 원스타 국밥집"*을 요구
- 음성 입력 자체는 **남습니다**(말하면 대화창에 텍스트로 적힘 = 접근성). 감정 분석·톤 적응만 제거
- 그동안의 튜닝 기록은 `ser-lab/STATUS.md`에 보관 — 지면이 남으면 "한계→개선" 사례로 재활용 가능

**② 시스템 아키텍처 도식이 없다는 걸 발견했습니다**
- 멘토가 **명시적으로** 요구: *"8~15개 컴포넌트 + 각 기술 스택 선정 근거"*
- 현재 기획안의 도식6은 유저플로우+처리흐름이지 아키텍처가 아님
- → SSOT §4에 **14개 컴포넌트 + 선정 근거**를 확정해 뒀습니다. 이걸로 도식을 만듭니다

기획서 서식은 **삽입자료 포함 5페이지**(운영사무국 공지 기준 10p)인데, 현재 도식 번호가 **13개**까지 잡혀 있습니다. **물리적으로 전부 못 넣습니다.**

배점 기준으로 정렬한 생존 순서:

| 순위 | 도식 | 상태 |
|---|---|---|
| 🥇 1 | **시스템 아키텍처** | 신규 (멘토 명시 요구, 현재 없음) |
| 🥇 2 | **T1 알고리즘 동작 다이어그램** | 신규 (시그니처) |

## 4. 🔴 팀 확정이 필요한 것 (개발 진행 블로커)

| # | 항목 | 왜 필요한가 | 담당 |
|---|---|---|---|
| A | **제도 노드 목록 + 선행조건 엣지** | 그래프 엔진의 입력 데이터. 이게 없으면 핵심 기능이 안 돕니다. 현재 KB 14건은 "카드"라 노드·엣지로 재구성 필요 | 개발 + 도메인 |
| B | **보유상태 케이스 테이블** (SSOT §6.6) | 정확도 지표의 채점 기준이자 테스트 픽스처 | 개발 + 도메인 |
| C | **수용(출소)증명서 조건·기한 검수** | 순환을 끊는 유일한 노드. 기한 "출소 후 10일"이 맞는지 확인 필요 | 공단 인터뷰 담당 |
| D | **NPS 측정 계획** | 멘토가 개발 목표 정량 지표로 요구 | 기획 |

## 5. 기존 도식이 "AI티 난다"고 지적받은 이유

멘토 지적을 구체화하면 원인은 5가지입니다:

1. **회색 플레이스홀더 막대** — 내용이 없다는 걸 그대로 그림
2. **"판독 필요"·"확인 필요" 라벨이 남아 있음** — 미완성 상태가 최종본에 노출
3. **모든 카드가 같은 크기·같은 여백** — 무엇이 중요한지 판단을 안 했다는 신호
4. **색 밴드가 의미를 인코딩하지 않음** — 색이 장식
5. **"접수 시스템"·"개인화" 같은 추상 명사** — 검증 불가능

> **판별 기준 한 줄: 사람이 그린 도식은 비대칭이다.** 중요한 게 크고, 실제 고유명사와 숫자가 박혀 있다.
> 재작성 시 미확정 항목은 도식에서 빼고 SSOT의 `[팀 확정]`으로 옮깁니다.

## 참고 — 멘토가 준 채점 힌트 (개발 관련만)

- **[난이도 상]** 가설을 3단계로 나눠 실행/개선 이터레이션 = **계단 효과**, 각 단계 한계 → 일부 극복

- 예선 마무리 시 **핵심 기능 1차 구현 완료** → 구현 가능성 만점
- 3번 섹션에서 모든 기술 나열은 지양 — 2장에서 끝낼 것
