# 마중365 — 개발 SSOT (2차 기획안 기준)

## 0. 이 문서가 존재하는 이유

멘토 피드백(2026-07-30): 개발 섹션은 **① 개발 목표(정량) ② User flow ③ System Architecture(8~15 컴포넌트 + 기술 선정 근거) ④ 개발 기능 리스트 ⑤ 핵심 기능 상세 — 알고리즘 설명 + 동작 다이어그램 + 세부 구조도**를 요구한다. 현재 2차 기획안 초안에는 **System Architecture 도식이 없고**, 알고리즘 명세가 산문으로만 존재한다. 이 문서가 그 값을 확정한다.

## 1. 한 문장 정의

> 출소자가 자기 상황을 말하면, 제도 간 **선행조건 그래프**를 연산해 **지금 실행 가능한 첫 과제 하나**를 제시하고, 완료하면 다음이 열리는 온보딩 내비게이터.

핵심은 **챗봇**이다. 음성은 입력 수단이지 기능이 아니다.

## 3. User Flow (터치포인트)

```
① 유입·설치     팜플렛 QR(안드로이드/아이폰) → 스토어 → 설치 후 바로 실행
② 가입          개인정보 입력(이름·생일·출소날짜·죄목) + 6분야 박스 문답 + 동의
③ 오늘 할 일    중요도순 아코디언 · 한 번에 하나만 펼침
④ 실행·완료     준비물 체크리스트 · 위치 · 소요 기간 사전 고지 · 탭 내 AI 채팅
⑤ 방문 알림     본인 동의 시 담당자에게 방문 정보 전달 → 채팅으로 조율
```

- ②→③ 사이에 처리 파이프라인(§6)이 돈다. 사용자에게는 보이지 않는다.
- ④ 완료 이벤트 → ③ 재계산(다음 과제 해금). **루프가 이 서비스의 형태다.**

> ⚠️ **2026-08-23 개정.** 초판의 ①(로그인 없는 3갈래 진입)과 ②(자유발화·버튼 선택)는
> 폐기되었다. **QR은 설치 링크일 뿐이고 계정은 가입 화면에서 만들어져 기기 자동 로그인된다.**
> 상황 입력은 자유발화가 아니라 **6분야로 묶인 문답**이며, 별도 질문 페이지 없이 가입 화면
> 안에서 박스를 눌러 답한다. 6개 분야를 모두 마쳐야 가입이 완료된다.
> 문항 전문은 `intake-questions.md`, 화면 구조는 리뉴얼 기획안 v2 §3을 따른다.

- 초판은 "보유 상태와 완료 여부만 저장한다"고 했으나 **지금은 개인정보와 대화 내역도 암호화해
  저장한다**(§10). 다만 대화 이력을 근거로 한 서사형 개인화("어제는 ~하셨네요")는 여전히 하지
  않는다. 이 서비스는 목표 하나를 제시하고 그 목표에 대해서만 대화한다.

**음성 입력의 위치:** ②의 입력 수단 3종 중 하나. GPT·Claude 앱의 음성 받아쓰기와 동일한 UX — 말하면 **대화창에 텍스트로 적힌다**. 사용자가 확인·수정 후 전송한다. 감정 분석·톤 적응은 하지 않는다.

### 4.2 기술 선정 근거

- **순서 계산을 LLM이 아닌 코드(C7)로 둔다.** 선행조건은 결정적 규칙이다. LLM에 맡기면 같은 입력에 다른 순서가 나올 수 있고, 잘못된 순서는 사용자를 헛걸음시킨다. 코드로 처리해 **재현성과 3초 응답을 동시에 확보**한다. LLM은 코드가 못 하는 두 곳 — 자유 발화에서 상태를 읽는 일(C6)과 사실을 사람의 말로 바꾸는 일(C10) — 에만 쓴다.
- **위상 정렬(Kahn).** 선행조건 관계는 DAG로 표현된다. 진입차수 0 노드 탐색은 O(V+E)로, 제도 수가 늘어도 응답 시간이 흔들리지 않는다.
- **STT 자체 호스팅(C3).** 출소 사실 자체가 극도로 민감한 정보다. 음성 원본을 외부 API로 보내지 않는 것이 데이터 최소화 원칙의 직접 구현이다. 오디오는 처리 후 즉시 폐기한다.
- **하이브리드 검색(C9).** 제도 코퍼스는 소규모·고품질 큐레이션이라 키워드 정합이 정밀하고, 벡터는 사용자가 제도명을 모른 채 다른 표현을 쓸 때를 보완한다. 실측에서 단독 방식은 각각 오검색이 있었고 하이브리드가 4/4 정확했다.
- **JSON 지식베이스(C8).** 예선 범위에서 DB는 과설계다. 제도 수가 수십 단위이고 갱신 주기가 길다. 본선에서 구조 변경 없이 DB로 승격 가능하도록 스키마를 먼저 고정한다.
- **Expo 단일 코드베이스(C1).** 예선은 웹 export, 본선은 같은 코드로 앱 빌드. 재작성 비용 0.

## 6. 핵심 알고리즘 — 선행조건 그래프 해결 (T1)

> 멘토 요구의 "알고리즘 설명 + 동작 다이어그램"이 붙는 지점. **이것이 메인 디쉬다.**

### 6.1 문제

제도 간 선행조건이 **순환**한다.

```
신분증 → (있어야 만든다) → 통장 → (있어야 받는다) → 긴급지원금
   ↑                                                      ↓
주소지 ← (있어야 등록한다) ← 거처 ← (있어야 구한다) ←──────┘
```

목록을 안내해도 시작할 수 없다. 필요한 것은 **이 순환을 어디서 끊을 것인가**다.
그리고 출소자가 가진 것은 제각각이다 — 아무것도 없는 사람, 신분증만 있는 사람, 다 갖추고 통장만 정지된 사람. **같은 목표라도 시작점이 다르다.**

### 6.2 자료구조

```
노드(제도/자원) : { id, name, 준비물[], 장소, 소요기간, 기한, kb_ref }
엣지(선행조건)  : requires(A → B)  "A를 하려면 B가 있어야 한다"
사용자 상태     : { 노드id: O | X | △ | ? }
```

- **O** 있음 · **X** 없음 · **△ 있으나 사용 불가**("통장은 있는데 정지됐어요") · **?** 모름
- **△가 이 도메인의 특이점이다.** 있음도 없음도 아니라 설문으로는 잡히지 않는다. 자유 발화에서만 드러나며, 연산에서는 X로 취급하되 챗봇이 되물어 확정한다.

### 6.3 절차

```
1. 상태 정규화   △·? → X 취급 (단, △·? 목록은 되물음 큐에 적재)
2. 만족 마킹     상태가 O인 노드를 '충족'으로 표시하고 그 엣지를 제거
3. 위상 정렬     남은 그래프에서 진입차수 0인 노드 집합 = 실행 가능한 시작점 후보
4. 순환 검출     후보가 공집합이면 데드락 → 예외 경로 탐색(§6.4)
5. 단일 선택     후보 중 1개만 제시 (우선순위 §6.5)
6. 되물음        △·? 큐에 항목이 있으면 과제 제시 후 1개만 확인 질문
```

- 복잡도 **O(V+E)**. 제도 수 증가에 선형.
- **한 번에 하나만 제시한다.** 여러 개를 주면 저리터러시 사용자는 다시 막힌다.

### 6.4 예외 경로 — 순환을 끊는 노드

전부 X인 최악의 경우에도 **선행조건이 없는 노드가 하나 존재**한다.

> **수용(출소)증명서** — 교정시설이 발급하며 신분증·주소지가 필요 없다. 그래프에서 유일하게 진입차수가 0인 노드.

여기서 순환이 풀린다:
```
수용증명서 → 긴급복지 생계지원 신청(출소일부터 6개월 이내)
          → 거처 확보 → 주소지 등록
          → 신분증 재발급 → 통장 개설 → 이후 취업지원 트랙 진입
```

> ✅ 2026-08-03 웹 검색으로 재확인: 긴급복지지원법 시행령의 교정시설 출소자 위기사유 조항은 "구금기간 6개월 이상 + **출소일부터 6개월 이내** 신청"을 요건으로 한다. 초판의 "10일"은 근거를 찾지 못해 폐기 — 아마 다른 절차(이의신청 처리기한 등)와 혼동된 값으로 추정. 6개월은 "며칠 안에 당장" 수준의 긴급함은 아니라 그래프 엔진의 우선순위 문구도 완화된 표현("서두르지 않아도 괜찮아요")으로 분리했다(graph_engine.py `_build_priority_reason`).

### 6.5 시작점 우선순위 (후보가 복수일 때)

1. **기한 임박** — 놓치면 자격이 사라지는 것 (예: 긴급복지 10일)
2. **해금 수** — 완료 시 열리는 후속 노드가 많은 것
3. **소요 기간 짧음** — 첫 성공 경험을 빨리 만든다

### 지금의 수집·저장 정책

| 항목 | 처리 |
|---|---|
| 이름 · 생일 · 출소날짜 | **수집하고 암호화해 DB에 저장한다.** 세 항목의 조합은 개인을 식별하므로 조합 단위로 보호 수준을 정한다 |
| 죄목 (대분류 6종) | **선택 항목.** 민감정보 준용 — 별도 동의 · 분리 저장 · 암호화. "말하고 싶지 않아요"를 고를 수 있다 |
| 주민등록번호 | **수집하지 않는다.** 고유식별정보에 해당하는 항목은 어떤 것도 받지 않는다 |
| 대화 내역 | **암호화해 저장한다.** 초판의 세션 종료 시 폐기는 폐기되었다 |
| 위치 좌표 | **서버로 보내지 않고 저장하지도 않는다.** 기기에서 시군구로 바꾼 뒤 시군구만 보낸다 |

> **전제가 하나 바뀌었다.** 저장하지 않을 때는 유출될 데이터 자체가 없었다. 저장하는 순간부터
> **"출소자 명단"이 실재하게 되며**, 이 데이터의 유출은 사용자의 사회 복귀를 직접 파괴한다.
> 아래 보호 장치는 선택 사항이 아니라 이 결정에 딸린 필수 조건이다.

### 유지되는 원칙

- LLM API 전송 전 **개인식별정보 로컬 마스킹**(C5)
- **음성 원본은 외부로 나가지 않는다** — STT 자체 호스팅, 처리 후 즉시 삭제
- 사용자가 자기 기록을 **열람·수정·삭제**할 수 있다
- 공단 전달은 **본인 동의 시점에만**, 전달 항목을 사전 표시
- **사용자에게 점수·등급·위험도를 부여하지 않는다.** 본 서비스는 지원 도구이지 평가 도구가 아니다
- 비밀은 커밋하지 않는다(.env only). 클라이언트 번들에 키 금지

### 새로 붙은 것

- **개인정보 수집·이용 동의를 가입 화면에서 받는다.** 죄목 동의는 반드시 별도 항목으로 분리한다
- 동의 시각과 동의 항목을 저장한다. 동의를 받았다는 사실 자체가 기록으로 남아야 한다
- 보유 기간은 **마지막 접속일로부터 1년**
- **위치정보는 개인정보보호법이 아니라 위치정보법의 규율을 받는다.** 변호사 확인 항목이며
  구현을 막는 사안은 아니다

## 13. 기존 도식 진단 — 왜 "AI티"가 나는가

폐기 대상(유저 플로우·화면 구조)의 문제와 재작성 기준:

| 문제 | 재작성 기준 |
|---|---|
| 회색 플레이스홀더 막대 = 내용 없음을 그대로 그림 | 실제 화면 텍스트·실제 제도명을 넣는다 |
| "판독 필요"·"확인 필요" 라벨 잔존 | 미확정 항목은 도식에서 제거하고 SSOT `[팀 확정]`으로 옮긴다 |
| 모든 카드가 같은 크기·라운드·여백 → 정보 위계 없음 | 중요한 노드를 크게, 부수적인 것을 작게 |
| 색 밴드가 의미를 인코딩하지 않음 | 색 = 책임 주체 또는 노드 종류로 고정하고 범례를 단다 |
| "접수 시스템"·"개인화" 같은 추상 명사 | 실제 이름(컴포넌트명·모델명·저장소명·숫자)을 박는다 |

> **판별 기준 한 줄:** 사람이 그린 도식은 **비대칭**하다. 중요한 게 크고, 실제 고유명사와 숫자가 박혀 있다.
