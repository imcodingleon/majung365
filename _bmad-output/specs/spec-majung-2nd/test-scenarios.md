# 마중365 본선 — 테스트 시나리오와 체크리스트

가상 사용자 둘과 담당자 하나로 전 기능을 훑는다. **두 사용자를 일부러 반대로 만들었다** — 한 명은 급하고 아무것도 없는 상태, 한 명은 안정적이고 대부분 갖춘 상태다. 같은 화면이 두 사람에게 다르게 보여야 정상이고, 똑같이 보이면 초기 진단이 답을 반영하지 않는 것이다.

> **먼저 읽을 것.** 체크가 실패했을 때 무엇이 잘못된 것인지를 각 항목에 함께 적었다. "안 나온다"와 "틀리게 나온다"는 다른 문제이고, 특히 **오류 없이 결과가 비는 경우**가 이 앱에서 반복해서 나타난 실패 모양이다.

## 등장 인물

### 사용자 A — 아무것도 없이 나온 사람

| 항목 | 값 |
|---|---|
| 이름 | 김성호 |
| 생일 | 1976년 3월 9일 |
| 출소한 날 | **오늘 기준 3일 전** |
| 어떤 일로 계셨는지 | **재산·경제범죄** (밝힘 → 민감정보 동의가 나타나야 함) |
| 위치 동의 | **켠다** (승인) |
| 제3자 제공 동의 | **켠다** |

**초기 진단 답** — 갈 곳도 신분증도 없는 상태로 잡는다.

```
주거        오늘 밤 잘 곳이 없어요 / 네, 지낼 집을 구해야 해요
            아니요, 예전에 살던 곳이나 다른 주소로 되어 있어요
생계·긴급비용  밥값과 생활비가 필요해요 / 신청은 안 했어요 / 오늘이나 며칠 안에 쓸 생활비가 없어요
신분·행정    아니요, 없어요 / 주민등록증은 신청 안 했어요 / 내 이름으로 된 통장이 없어요
취업·직업    아니요, 일을 찾고 있어요 / 바로 일자리를 찾고 싶어요 / 아니요(허그일자리)
건강·심리    병원에 가거나 약을 받아야 해요 / 네, 상담받고 싶어요
기타·권리구제  없어요(출소증명서) / 처음 알아보는 중이에요 / 확인 안 했어요
```

**기대: 할 일이 여러 개 나오고 R9·R11이 포함된다.**

### 사용자 B — 자리를 잡아가는 사람

| 항목 | 값 |
|---|---|
| 이름 | 박정미 |
| 생일 | 1990년 11월 22일 |
| 출소한 날 | **오늘 기준 8개월 전** |
| 어떤 일로 계셨는지 | **말하고 싶지 않아요** (→ 민감정보 동의가 **나타나지 않아야** 함) |
| 위치 동의 | **끈다** 또는 기기에서 거부 |
| 제3자 제공 동의 | **끈다** |

**초기 진단 답** — 대부분 해결된 상태로 잡는다.

```
주거        계속 지낼 곳이 있어요 / 지금은 필요 없어요
            네, 지금 지내는 곳으로 되어 있어요
생계·긴급비용  지금은 필요 없어요 / 지금 받고 있어요
신분·행정    네, 있어요 / 지금 쓸 수 있어요
취업·직업    네, 일하거나 사업을 하거나 학교에 다녀요 / 지금은 필요 없어요
건강·심리    지금은 필요 없어요 / 지금은 필요 없어요
기타·권리구제  있어요 / 지금은 필요 없어요 / 건강보험을 쓰고 있어요
```

**기대: 할 일이 A보다 눈에 띄게 적다.** 둘이 비슷하면 판정이 답을 안 보는 것이다.

### 담당자 C·D — 둘이 필요하다

**요청은 지역이 아니라 지원 항목으로 갈린다.** 계정 하나로는 절반밖에 못 본다.

| 계정 | 비밀번호 | 소속 | 받는 항목 |
|---|---|---|---|
| `admin1` | `admin1234` | 법무보호복지공단 경기지부 | R1 숙식 · R2 긴급지원 · R3 기초건강 · **R4 주거** · **R6 취업** · R7 창업 · R8 심리상담 |
| `admin2` | `admin1234` | 행정복지센터 경기 | **R9 신분증** · **R11 주소** · R12 생계급여 · R15 의료급여 |

**아무도 받지 않는 항목이 셋 있다** — R10(통장·은행) · R13(증명서·교정시설) · R14(빚·법원). 이 항목에 방문 요청을 보내면 서버가 400으로 막고 **"이 항목은 방문 예약 대신 안내된 창구로 바로 가시면 돼요"**가 돌아온다. 받아 두고 아무도 안 보는 것보다 낫다는 판단이다.

> **지부 필터는 꺼져 있다.** 어느 지부로 보냈든 한 화면에서 받는다. "경기지부로 온 요청만 보입니다"라고 적혀 있어도 실제로는 안 걸러진다 — 서버가 사용자 지역을 모르기 때문이다. 시연에서 문제되지 않지만 **문구와 동작이 다르다는 것은 알고 있어야 한다.**

## 플로 1 — 가입 (사용자 A)

### 1-1. 화면 진입

- [ ] 앱을 처음 열면 가입 화면이 나온다 (진입 코드 입력 같은 관문이 없다)
- [ ] 상단에 마중365 로고와 "도움이 필요해요" 버튼이 있다
- [ ] **데스크톱 브라우저에서 화면이 가로로 늘어나지 않는다.** 가운데 모바일 폭으로 묶여 있다

  > 늘어나면 `AppFrame`이 안 걸린 것이다.

### 1-2. 이름·날짜

- [ ] 이름을 적는다
- [ ] 생일 "년" 칸을 누르면 팝업이 뜨고, 고르면 그 칸에 값이 들어간다
- [ ] **날짜를 고른 그 클릭이 뒤 화면의 죄목을 누르지 않는다**

  > 이게 실제로 났던 결함이다. 죄목은 별도 동의를 받는 민감정보라, 고른 적 없는 값이 들어가면 안 된다.

- [ ] 월·일도 같은 방식으로 들어간다
- [ ] 출소한 날도 마찬가지다
- [ ] **팝업이 열린 채로 다른 칸을 눌러도 새로 연 팝업이 곧바로 닫히지 않는다**

  > 닫히면 미뤄둔 닫기가 새 팝업을 덮친 것이다. 제목과 단위가 빈 목록이 보이면 같은 증상이다.

### 1-3. 죄목

- [ ] 목록에서 "재산·경제범죄"를 고른다
- [ ] **"말하고 싶지 않아요"가 다른 선택지와 같은 간격으로 붙어 있다** (따로 떨어져 있지 않다)
- [ ] 아래 동의란에 **[필수] 민감정보 수집·이용 동의**가 새로 나타난다

  > 나타나지 않으면 §3.4-2가 깨진 것이다. 밝히지 않은 정보에 동의를 받으면 안 되고, 밝혔으면 반드시 받아야 한다.

### 1-4. 상황 알아보기 (6분야)

- [ ] 6분야가 2×3 격자로 보이고 각각 아이콘이 있다
- [ ] "주거"를 누르면 문항 팝업이 전체 화면으로 열린다
- [ ] 진행 표시가 "3개 중 1번째"처럼 나온다
- [ ] 답을 고르기 전에는 "다음"이 흐리고 **"답을 고르시면 다음으로 갈 수 있어요."**가 보인다

  > "다음으로 넘어가요"로 적혀 있으면 낡은 문구다. 저절로 넘어간다고 읽혀 사용자가 기다리게 된다.

- [ ] "오늘 밤 잘 곳이 없어요"를 고른다
- [ ] **다음 문항이 "지금 머무는 곳은 언제까지 있을 수 있나요?"가 아니다**

  > 잘 곳이 없다고 했는데 머무는 곳의 기한을 물으면 모순이다. 꼬리질문 조건이 깨진 것이다.

- [ ] 답에 따라 문항 수가 늘어난다 (3개 → 5개)
- [ ] "이전"으로 돌아가면 앞서 고른 답이 그대로 있다
- [ ] 마지막 문항에서 버튼이 **"다 답했어요"**로 바뀐다
- [ ] 누르면 팝업이 닫히고 그 분야에 **"✓ 다 답했어요"**가 표시된다
- [ ] **팝업이 닫히는 클릭이 뒤의 다른 분야를 눌러 새 팝업을 열지 않는다**
- [ ] 나머지 다섯 분야도 마친다. 위 진행 표시가 "6개 중 6개"가 된다

### 1-5. 응급 안내

- [ ] 건강·심리 첫 문항에서 **"지금 바로 치료받아야 해요"**가 빨간 글씨로 강조되어 있다
- [ ] 그것을 고르면 화면을 덮는 안내가 뜨고 **119 전화 버튼**이 있다
- [ ] 확인 절차 없이 바로 걸리는 자리다 (버튼을 실제로 누르지는 말 것)
- [ ] 안내를 닫으면 문항으로 돌아오고 답이 유지된다

### 1-6. 동의

- [ ] 항목이 **[필수]/[선택]** 표시와 함께 나온다
- [ ] 각 항목의 "보기 ›"를 누르면 약관 전문이 열린다
- [ ] **약관이 법정 고지 형식이다** — 근거 법령, 목적, 항목, 보유 기간, 거부 권리가 조항으로 나뉘어 있다

  > "쉬운 말"로 쓰여 있으면 낡은 판이다. 동의란은 사용자가 다른 서비스에서 익힌 형식을 따라야 한다.

- [ ] **[선택] 위치 정보 이용 동의**가 있다
- [ ] 체크하면 **그 자리에서** 기기 위치 권한 팝업이 뜬다
- [ ] 승인하면 동의란 안에 **"서울특별시 송파구 오금동"**처럼 지금 있는 곳이 파란 글씨로 나온다
- [ ] **거부하면 체크가 자동으로 풀린다**

  > 켜져 있는데 위치가 안 잡히는 상태로 남으면, 나중에 왜 근처 기관이 안 나오는지 알 길이 없다.

- [ ] **권한 팝업을 그냥 두면 15초 뒤에 "못 찾았어요"로 넘어간다**

  > 이것도 실제로 났던 결함이다. 영원히 "알아보고 있어요…"에 멈춰 있으면 시간 제한이 안 걸린 것이다.

- [ ] 위치 약관을 열면 **보유 기간에 "위치정보를 보유하지 않습니다"**라고 적혀 있다
- [ ] "약관 전체 동의"를 누르면 모두 켜지고, 위치 권한도 함께 요청된다
- [ ] 필수를 하나라도 끄면 "시작하기"가 흐려진다

### 1-7. 가입 완료

- [ ] "시작하기"를 누르면 홈으로 넘어간다
- [ ] **할 일이 여러 개 나온다**

  > **0개면 답변 키가 어긋난 것이다.** 오류가 안 나고 목록만 비는 형태라 화면에서는 "해당 없음"으로 보인다.

- [ ] 인사말에 이름이 나온다

## 플로 2 — 오늘의 할 일 (사용자 A)

### 2-1. 목록

- [ ] 할 일이 카드 목록으로 나온다
- [ ] 첫 항목이 열린 채로 시작한다
- [ ] 선행 항목이 있는 카드에 **"먼저 하면 좋아요"** 표시가 있다

  > "긴급도 높음"으로 적혀 있으면 낡은 문구다. 서버 값은 선행조건이지 급한 정도가 아니다.

- [ ] 다른 카드를 누르면 그것이 열리고 앞의 것이 닫힌다 (한 번에 하나)

### 2-2. 카드 안

- [ ] 창구 안내가 파란 상자로 나온다 ("○○에 가서 '○○'라고 말하면 돼요")
- [ ] **그 바로 아래에 "가까운 곳" 구역이 있고 기관 이름과 주소가 나온다**
- [ ] 사는 동의 주민센터에 **"여기예요"** 표시가 붙는다
- [ ] 신분증 항목(R9)에는 **"어느 주민센터에서나 하실 수 있어요"**가 함께 나온다
- [ ] **주소 항목(R11)에는 근처 주민센터가 나오지 않는다**

  > 전입신고는 새 주소지 관할이라 지금 있는 곳을 짚으면 틀린 곳으로 보내게 된다. 나오면 안 되는 것이 나온 경우다.

- [ ] 준비물 목록이 나온다
- [ ] 연락처가 회색 상자로 나오고 **전화번호 뒤 조사가 맞다** ("1588-1234로", "1670-7004로")
- [ ] 확인 날짜가 **버튼 아래**에 작게 나온다

  > ✓ 표시를 달고 안내 목록에 섞여 있으면 낡은 판이다. 할 일처럼 읽힌다.

### 2-3. 완료 루프

- [ ] "이 일을 끝냈어요"를 누른다
- [ ] **그 항목이 목록에서 빠지고 다음 항목이 열린다**
- [ ] 진행 표시(○개 중 ○개)가 줄어든다
- [ ] 앱을 새로고침해도 완료가 유지되는지 확인한다

  > 웹은 세션이 메모리에만 있어 새로고침하면 가입 화면으로 돌아간다. **앱에서만 유지된다.**

### 2-4. 기관 찾기

- [ ] 목록 끝에 **"📍 우리 동네 기관 찾아보기"**가 있다
- [ ] 누르면 기관 안내 화면이 열린다
- [ ] 지금 있는 곳이 제목에 나온다
- [ ] 주민센터·정신건강복지센터·공단이 구역별로 나온다
- [ ] **다른 구의 정신건강복지센터가 섞여 나오지 않는다**

  > 서버는 시도 단위로 주므로, 전부 그리면 송파구 사람에게 강남구 센터가 나온다.

- [ ] 주민센터에는 전화번호가 없다 (원본 데이터에 없는 값이다)
- [ ] 공단·센터는 전화번호가 있고 누르면 전화 앱이 열린다

## 플로 3 — AI 채팅 (사용자 A)

- [ ] 카드에서 "AI 챗봇과 대화하기"를 누르면 팝업이 전체 화면으로 열린다
- [ ] **팝업이 모바일 프레임 안에 들어온다** (데스크톱에서 가로로 퍼지지 않는다)
- [ ] 질문을 보내면 답이 한 글자씩 흘러나온다 (스트리밍)
- [ ] 답 아래에 근거 배지가 붙는다

**확인한 자료로 답한 경우**

- [ ] 배지에 **"확인한 자료를 참고했어요"**가 나온다
- [ ] 카드 말풍선에는 **"이 안내는 마중365가 ○년 ○월 ○일에 확인했어요."**가 나온다
- [ ] **카드 말풍선에 배지와 확인 날짜가 함께 나오지 않는다** (같은 말을 두 번 하는 것)

**인터넷에서 찾은 경우**

- [ ] 검색 **전에** "지금 가지고 있는 자료에서는… 인터넷에서 찾아볼게요."가 먼저 나온다
- [ ] 배지가 노란색이고 **"인터넷에서 찾은 내용이에요"**가 나온다
- [ ] 그 아래에 **"전화로 한 번 확인해 보세요."**가 굵게 나온다

**주민센터 질문**

- [ ] "나 지금 송파구 오금동 사는데 근처 주민센터 알려줘"라고 묻는다
- [ ] **오금동 주민센터의 이름과 주소가 답에 나온다**

  > "자료에 없어요"라고 하며 인터넷 검색을 권하면 챗봇이 주민센터 데이터를 못 보는 것이다.

- [ ] "중앙동 주민센터 어디예요"라고 물으면 **여러 곳이 있다며 시·군·구를 되묻는다**
- [ ] 답변 끝에 담당 기관 연락처가 붙는다

**마스킹**

- [ ] "제 번호는 010-1234-5678이에요"라고 보낸다
- [ ] 답이 번호를 그대로 되받아 적지 않는다

## 플로 4 — 담당자 방문 알림 (사용자 A → 담당자 C·D)

**두 계정을 다 써야 한다.** 아래 4-1을 두 번 한다 — 한 번은 **R9(신분증)**로 보내 `admin2`에서 받고, 한 번은 **R6(취업)**으로 보내 `admin1`에서 받는다. 한쪽만 하면 배정 규칙이 도는지 확인되지 않는다.

### 4-1. 요청 보내기

- [ ] 카드에서 "○○ 담당자에게 미리 알리기"를 누른다
- [ ] 시간 후보가 평일 오전·오후로 나온다 (주말이 없다)
- [ ] 1지망과 2지망을 고른다. **같은 시간을 두 번 못 고른다**
- [ ] 준비물 체크가 있다
- [ ] **"상황 알아보기에서 답한 내용도 함께 보내기"** 체크가 있다
- [ ] 체크하면 분야별로 켜고 끌 수 있고, **방문 목적과 같은 기관 분야가 처음부터 켜져 있다**
- [ ] "어떤 일로 계셨는지는 알려주지 않아요"가 적혀 있다
- [ ] 보내는 동안 버튼이 **"보내는 중이에요"**로 바뀌고 두 번 눌리지 않는다
- [ ] 보내고 나면 카드에 **"담당자에게 전달했어요. 확인하면 알려드릴게요."**가 나온다

### 4-2. 받지 않는 항목

- [ ] R10(통장)·R13(증명서)·R14(빚) 카드에는 **"담당자에게 미리 알리기" 버튼이 없거나**, 눌렀을 때 안내가 나온다
- [ ] 서버가 400으로 막으면 화면에 **"이 항목은 방문 예약 대신 안내된 창구로 바로 가시면 돼요"**가 나온다

  > 오류 문구가 그대로 나오거나 아무 반응이 없으면, 서버가 준 문구를 화면이 안 쓰는 것이다.

### 4-3. 상한

- [ ] 같은 할 일로 또 보내려 하면 **"이 일로 이미 보낸 요청이 있어요"**가 나온다
- [ ] 하루에 세 번 보낸 뒤 또 보내면 **"오늘은 세 번 보내셨어요"**가 나온다
- [ ] 막히더라도 **이미 보낸 요청이 함께 보인다** (그냥 막기만 하지 않는다)

### 4-4. 담당자 쪽

- [ ] `admin2 / admin1234`로 로그인한다 (R9 요청을 받는 쪽)
- [ ] 나중에 `admin1 / admin1234`로도 로그인해 **R6 요청이 그쪽에만 보이는지** 확인한다
- [ ] **R9 요청이 admin1 화면에 보이지 않는다** (반대도 마찬가지)
- [ ] 상단에 **소속 기관과 지부명**이 나온다
- [ ] "○○으로 온 요청만 보입니다"가 적혀 있다
- [ ] A가 보낸 요청이 목록에 있고 **"새 요청"** 배지가 붙어 있다
- [ ] 아직 확인하지 않은 요청이 위로 올라와 있다
- [ ] 요청을 열면 이름·방문 목적·1·2지망·준비물이 나온다
- [ ] **죄목이 어디에도 없다**
- [ ] **"본인이 미리 알려 온 것"** 구역에 진단 답변이 나온다
- [ ] 답변이 **방문 목적에 가까운 순서**로 정렬되어 있다 (그 항목 → 같은 기관 → 다른 기관)
- [ ] 안 챙겨 오는 준비물이 노란 상자로 표시된다
- [ ] "확인했습니다"를 누르면 상태가 바뀐다

### 4-5. 확정

- [ ] 만날 시간·담당자 이름·장소를 채우고 확정한다
- [ ] **장소가 비면 확정할 수 없다**
- [ ] 사용자 화면에 **"○월 ○일 ○요일 오전으로 정해졌어요. ○○에서 ○○ 담당자를 찾으세요."**가 나온다
- [ ] **시간이 자정이나 새벽이 아니다**

  > `confirmed_at`(확정을 누른 시각)을 방문 시각으로 쓰면 새벽이 나온다.

- [ ] **"담당자 담당자를 찾으세요"처럼 말이 겹치지 않는다**
- [ ] 조사가 맞다 ("오전으로" / "오후로", "김민수 담당자를" / "박지훈 주무관을")

### 4-6. 시간 변경 제안

- [ ] 담당자가 다른 시간을 제안한다
- [ ] 사용자 화면에 제안 시간과 **"그때 갈게요" / "다시 정할게요"** 버튼이 나온다
- [ ] 수락하면 확정 문구로 바뀐다

### 4-7. 취소

- [ ] 사용자 화면 상태 띠 아래에 **"안 가게 됐어요"**가 작은 밑줄 글씨로 있다
- [ ] **확정 전에는 누르면 바로 취소된다**
- [ ] **확정된 요청은 "담당자가 시간을 비워 두었어요. 정말 안 가시겠어요?"를 한 번 묻는다**
- [ ] 취소하면 목록에서 사라지지 않고 **취소된 상태로 남고 "다시 보내기"가 나온다**
- [ ] 담당자 화면에서도 취소로 보인다
- [ ] 담당자가 취소한 경우 **사유가 사용자 화면에 함께 나온다**

### 4-8. 담당자 채팅

- [ ] 담당자가 확인하기 **전에는** "담당자와 이야기하기"가 없다
- [ ] 확인한 뒤에 나타난다
- [ ] 양쪽에서 메시지를 주고받는다
- [ ] **내 말풍선과 상대 말풍선이 좌우로 갈린다**

  > 전부 한쪽에 붙으면 보낸 사람 구분 필드가 어긋난 것이다.

## 플로 5 — 위치를 거부한 경우 (사용자 B)

같은 화면이 위치 없이도 성립하는지 본다.

- [ ] 가입할 때 위치 동의를 **끈 채로** 진행한다
- [ ] 가입이 정상으로 끝난다 (선택 항목이므로 막히지 않는다)
- [ ] **죄목을 "말하고 싶지 않아요"로 골랐으므로 민감정보 동의가 나타나지 않는다**
- [ ] 홈에서 **할 일이 A보다 눈에 띄게 적다**
- [ ] 카드에 **"가까운 곳" 구역이 나오지 않는다** (빈 상자가 남지 않는다)
- [ ] "우리 동네 기관 찾아보기"를 누른다
- [ ] **"지역을 직접 고를게요"** 경로가 있다
- [ ] 시도와 시군구를 고르면 그 지역 기관이 나온다
- [ ] 기관이 없는 지역을 고르면 **"이 지역에서 찾아가실 곳을 아직 못 찾았어요. 1670-7004로 전화하시면 알려드려요."**가 나온다

  > "우리가 그 지역 정보가 없어요"라고 사과하는 문구가 나오면 §5.4 위반이다.

- [ ] **제3자 제공에 동의하지 않았으므로 카드에 "담당자에게 미리 알리기"가 없다**

## 플로 6 — 내 정보 (사용자 A)

- [ ] 내 정보 화면에 들어가려면 **생일을 먼저 확인한다**
- [ ] 틀리게 넣으면 못 들어간다
- [ ] 이름·생일·출소한 날이 보인다
- [ ] **죄목 값이 그대로 보인다** ("재산·경제범죄")

  > §2.5가 이 화면을 "이름·생일·출소날짜·죄목 전부"가 노출되는 지점으로 적고, 조정 방법을 "이 화면에 들어갈 때만 확인 절차를 둔다"로 정했다. 가리는 것이 아니라 **문을 잠그는** 쪽이다.
- [ ] **"어떤 일로 계셨는지 지울까요?"** — 죄목만 지우는 경로가 있다
- [ ] 지우면 **계정은 그대로 남고 죄목만 사라진다**
- [ ] **"모든 정보를 지울까요?"** — 계정 전체 삭제가 별도로 있다
- [ ] 삭제하면 가입 화면으로 돌아가고 다시 들어갈 수 없다
- [ ] 삭제 전에 **무엇이 지워지는지** 안내가 나온다

## 플로 7 — 화면 공통

- [ ] **데스크톱 브라우저에서 모든 화면이 모바일 폭으로 묶인다**
- [ ] **모든 팝업이 프레임 안에 들어온다** (날짜·문항·약관·채팅·방문 요청·응급·도움)
- [ ] 반투명 덮개가 있는 팝업은 **프레임 밖이 비어 있어 뒤 화면이 보인다**
- [ ] 글씨가 크다 (저리터러시 전제)
- [ ] 화면 어디에도 **"죄목"·"설문"·"영역"**이라는 말이 없다
- [ ] 어디서든 **"도움이 필요해요"**로 전화 안내에 닿는다

## 실패했을 때 먼저 볼 것

이 프로젝트에서 반복해서 나온 실패 모양들이다.

| 증상 | 대개의 원인 |
|---|---|
| 오류는 없는데 목록이 빈다 | 이름·키 형식이 서버와 어긋남. 오류가 안 나므로 "해당 없음"으로 보인다 |
| 누구에게나 같은 할 일이 나온다 | 판정 규칙표가 비어 있어 답을 안 봄 |
| 팝업을 닫는 클릭이 뒤 화면을 누른다 | 웹에서 팝업을 그 자리에서 닫으면 click이 아래로 샌다 |
| 화면이 "…하는 중"에서 안 돌아온다 | 끝나지 않는 약속. 시간 제한이 없다 |
| 시각이 자정이나 새벽으로 나온다 | 처리 시각을 방문 시각으로 씀 |
| 조사가 어긋난다 ("오후으로") | 값에 따라 갈리는 조사를 고정해 둠 |
| 말풍선이 전부 한쪽에 붙는다 | 보낸 사람 필드 이름이 어긋남 |

## 미리 만들어 둔 시연 데이터

서버에 상태를 맞춰 둔 요청이 둘 있다. **지우지 말 것.**

```
24702de6…   R1   공단      acknowledged   ← admin1 화면. 담당자 채팅 확인용
7a01f343…   R9   주민센터   confirmed      ← admin2 화면. 확정 문구 확인용
```

`reschedule_proposed`(담당자가 다른 시간을 제안한 상태)는 아직 만들어진 것이 없다. 플로 4-6을 직접 눌러 만들거나, 백엔드에 그 상태로 하나 만들어 달라고 하면 된다.

## 아직 확인 못 한 것

- **홈 화면의 근처 기관·취소 버튼** — 데이터 흐름은 서버로 검증했으나 화면에서 눈으로 확인하지 못했다. 브라우저 렌더러가 반복해서 멈춰 가입을 통과하지 못했다
- **지부 필터** — 꺼져 있어서 "○○으로 온 요청만 보입니다" 문구와 실제 동작이 다르다
